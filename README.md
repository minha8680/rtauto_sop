# rtauto_sop

**작업자 행동인식 기반 SOP 준수 지원 시스템** — AI 모델 학습/검증 저장소

알티자동화(RT Automation)의 시범 과제입니다. 이 저장소는 전체 시스템 중 **객체 검출 모델을
준비·검증하는 파트**만 담고 있습니다.

**현재 진행**: 안전모 착용/미착용 검출 모델 확보 완료(helmet_v2). 다음은 인원 수 검출 + 추적.

---

## 1. 시스템 개요

작업자 2인 1조 작업을 카메라로 검출해 엣지 PC가 SOP(표준작업절차)와 대조하고, 편차가
확정되면 작업자에게는 헤드셋 음성으로, 관리자에게는 휴대폰 알림으로 즉시 통보합니다.

- **시범 대상**: 세정기 작업
- **카메라 구성**: 현장 고정이 아닌 **착용형(체스트 마운트)**. 실제 작업자 1인 + 안전감시단원
  1인이 각각 바디캠을 착용(총 2대). 설비 형상·위치가 바뀌어도 같은 구성을 그대로 사용.
- **처리 위치**: 영상·음성 모두 현장 엣지 PC 1대에서 처리. 사무실 서버·관제 PC 없음.
  인터넷 회선 1개만 있으면 동작하며, 인터넷이 끊겨도 현장 경보는 계속 울림.

### 감지 항목

본사 SOP 양식에서 다음 4가지를 검출 대상으로 정의합니다.

| SOP 문서 항목 | 시스템 판정 항목 | 주 검출 경로 |
|---|---|---|
| 항목·순서 | 단계 순서 위반 · 단계 누락 | 작업자 바디캠 (근접 시점) |
| 급소포인트 | 필수 동작 누락 · 확인 절차 생략 | 작업자 바디캠 (0.8m 이내) |
| STEP별 작업시간 | 표준 소요시간 초과 · 과속 진행 | 양 카메라 공통 (체류시간) |
| 위험요인 | 안전구역 침범 · 위험 자세 | 감시단원 바디캠 (광역 시점) |
| 안전관리대책 | 2인 1조 인원 수 · 보호구 착용 | 감시단원 바디캠 (2~4m) |

## 2. AI의 역할

**AI는 객체 검출 · 추적 · 음성 인식(STT)에만 사용합니다.** 편차 판정과 응답 문구는 규칙
기반으로 처리하여, 판정 근거를 사람이 그대로 추적할 수 있게 합니다.

- 사람 · 안전보호구 같은 범용 객체는 **공개 사전학습 모델을 그대로 사용**하는 것이 기본
  방침입니다(별도 학습 비용 없음).
- 세정기 특유의 부품이나 급소포인트 동작처럼 공개 모델이 다루지 않는 항목만, 소량의 현장
  영상으로 미세조정(fine-tuning)합니다. 항목별 필요 여부는 1주차 현장 실측에서 확정합니다.
- **이 저장소의 헬멧 검출 실험**은 위 "보호구 착용" 항목이 공개 데이터/모델로 어느 정도
  커버되는지 사전 검증하는 작업입니다. → 아래 6절 결과 참고.

### AI 처리 흐름 (영상 경로)

```
① 스트림 수신(RTSP/H.264, FFmpeg 3fps)
② 객체 검출 (YOLO 계열 1-stage: 사람·안전모·장갑 …)      ← 현재 여기 (안전모 완료)
③ 추적·좌표화 (ByteTrack, 중복 제거, 구역 좌표 매핑)
④ 상태 집계 (인원 수·보호구·구역 체류·자세, 3초 창 다수결)
⑤ SOP 대조 (구조화된 SOP와 STEP 순서·표준시간 규칙 비교)
⑥ 편차 확정 (중대/주의/정상 등급 산정 → 출력 라우팅)
```

음성 경로는 헤드셋 PTT 버튼 입력 시에만 채널이 열리며(상시 녹음 아님), `faster-whisper`로
STT 후 키워드 규칙으로 의도를 분류해 SOP를 조회하고 TTS로 응답합니다.

## 3. 세정기 SOP 표준 문서

시스템의 판정 기준은 SOP를 구조화한 데이터입니다. 자사 SOP에 세정기 작업이 없어, 이번
과제에서 「세정기 작업 표준 문서(SOP)」를 직접 제작합니다.

현장 관찰·영상 촬영 → 작업 단계 분해 → 표준 소요시간 측정 → 급소포인트·위험요인 도출 →
현장 검토·승인 → 승인 문서를 JSON으로 변환해 판정 엔진에 적재. 산출물이 문서와 시스템
양쪽에 남고, 다른 설비로 확장할 때는 같은 양식의 SOP를 JSON으로 바꿔 끼우면 됩니다.

## 4. 데이터 흐름 (전송 구간)

| 구간 | 데이터 | 매체 | 규격 | 지연 목표 |
|---|---|---|---|---|
| ① 바디캠 → 엣지 PC | 영상 2채널 | WiFi 5GHz (SoftAP 직결, 인터넷 미경유) | RTSP / H.264 · 1080p 15fps · 대당 ~4 Mbps | 0.5초 이내 |
| ② 헤드셋 ↔ 엣지 PC | 음성 질의/경보 | Bluetooth 5.x (USB 동글) | HFP 양방향 · 16kHz 모노 · 버튼 입력 시에만 개방 | 0.3초 이내 |
| ③ 엣지 PC → 관리자 휴대폰 | 편차 알림·클립 링크 | 인터넷 (유선 랜) | HTTPS + Web Push · 미확인 시 30초 간격 재발송 | 1초 이내 |

- 영상 경로(①)와 알림 경로(③)는 **물리적으로 분리**되어, 인터넷이 끊겨도 영상 수신과 현장
  경보는 그대로 동작합니다.
- 무선 특성상 순간 끊김이 생길 수 있어, **끊긴 구간은 "위반 없음"이 아니라 "판정 보류"**로
  이력에 남깁니다. 각 연결은 1초 주기 heartbeat로 확인하고 3회 연속 미수신 시 단절로 판정합니다.

## 5. 관리자 알림

전용 앱 없이 표준 **Web Push**를 사용합니다(Android/iOS 구성 동일). 엣지 PC가 알림
수신용 웹페이지를 제공하고, 관리자가 홈 화면에 한 번 추가 후 알림을 허용하면 끝입니다.

놓침 방지 3단계: ① 잠금화면 푸시에서 색·문구로 중대 편차 구분 → ② 탭하면 전체화면 경보
(경보음·진동 반복) → ③ 확인 버튼 누를 때까지 30초 간격 재발송.

> iOS는 16.4 이상에서 홈 화면 추가 시에만 Web Push가 동작하며, 잠금화면 알림음은 OS
> 기본음으로 고정됩니다.

## 6. 학습 결과 — 안전모 착용/미착용 검출

공개 데이터만으로 "보호구 착용" 항목을 판정할 수 있는지 검증한 실험입니다.

| | helmet_v1 | **helmet_v2** |
|---|---|---|
| 데이터셋 | `hard-hat-detection-ws2wk` (668장, 착용 위주) | `joseph-nelson/hard-hat-workers` (~7,000장) |
| 클래스 | hard hat / no hard hat / not hard hat | helmet / no_helmet (person 제외) |
| 미착용 학습 표본 | 16 ~ 64 인스턴스 | 1,000+ 인스턴스 |
| mAP@50 | 0.41 | **0.96** |
| 착용 검출률 (recall) | 0.91 | **0.97** |
| **미착용 검출률 (recall)** | **0.00 ~ 0.33** | **0.95** |

- helmet_v1과 v2는 **학습 설정이 동일**하고 데이터셋만 다릅니다. 미착용 표본을 늘리자 미착용
  검출률이 0 → 0.95로 올랐습니다. → **성능 한계는 학습량이 아니라 데이터에 있었음**을 확인.
- 이 시스템의 핵심 판정 대상인 **보호구 미착용(SOP 위반) 검출이 공개 데이터로 가능**함을
  확인했습니다. 단, 현장 조건(바디캠 화각·거리·조도)에서의 성능은 1주차 실측으로 별도 검증 필요.
- 상세: [`docs/helmet_v1/metrics.md`](docs/helmet_v1/metrics.md), [`docs/helmet_v2/metrics.md`](docs/helmet_v2/metrics.md),
  [`docs/helmet_v2/webcam_test.md`](docs/helmet_v2/webcam_test.md)

가중치 파일(`*.pt`)은 용량 문제로 저장소에 포함하지 않습니다 (로컬 `models/` · Google Drive 보관).

### 웹캠 테스트에서 확인한 것

로컬 웹캠 근접 조건에서 helmet_v2는 착용/미착용을 신뢰도 있게 구분합니다(confidence 0.7~0.9).
다만 다음은 다음 단계 설계에 반영해야 합니다.

- **"helmet 검출 = 착용"이 아님** — 손에 든 헬멧도 `helmet`으로 잡힘. 실제 착용 판정은
  person/head 박스와 helmet 박스의 공간 관계(겹침)로 규칙 단계에서 처리해야 함.
- **가림에 취약** — 얼굴이 가려지면 인물 자체가 미검출 → "위반 없음"이 아니라 판정 보류 처리.
- **원거리 소형 객체(2~4m, 안전모 22~35px) 성능은 미검증** — 바디캠 입고 후 현장 실측 대상.

### 현재 완성도

지금까지 완료한 것은 **위 감지 항목 4가지 중 "보호구 착용"의 안전모 부분 하나**입니다.
추적, 인원 수 카운팅, SOP 규칙 판정 엔진, 음성 경로, 알림, 엣지 PC 통합은 아직 착수 전입니다.
바디캠이 입고되면 "시스템이 바로 동작"하는 것이 아니라, helmet_v2 모델의 현장 성능 검증과
이후 개발 단계(현장 데이터 수집, 규칙 튜닝)를 진행할 수 있게 됩니다.

## 7. 이 저장소 사용법

### 환경

- Windows + Git Bash, Python 가상환경(`venv/`)
- 로컬 GPU는 GTX 1050 Ti(4GB)로 학습엔 약함 → **학습은 Google Colab (T4), 로컬은 추론만**
- 로컬 `torch`는 CPU 빌드. 추론(웹캠)은 CPU로 실시간 충분

```bash
source venv/Scripts/activate      # 가상환경 활성화
```

### 학습 (Google Colab)

1. Colab 새 노트북 → 런타임을 T4 GPU로 설정
2. 이 저장소 clone, `pip install ultralytics roboflow`
3. Colab Secrets(🔑)에 `ROBOFLOW_API_KEY` 등록 후 데이터셋 다운로드
4. data.yaml 경로 수정 + (필요 시) 클래스 재매핑
5. `YOLO("yolov8n.pt").train(data=..., epochs=50, imgsz=640, batch=32, device=0)`
6. `best.pt`, `results.png`, `confusion_matrix.png`, `results.csv` 를 `files.download()` 로 내려받기
7. 로컬 `models/` · `docs/<name>/` 에 배치 후 커밋

### 추론 (로컬)

```bash
python webcam_helmet.py   # 안전모 착용/미착용 웹캠 테스트 ('q' 종료). MODEL_PATH / CONF 는 파일 상단
python webcam_person.py   # 인원 수 + ByteTrack 추적 + "2인 1조" 규칙(3초 지속) 데모
python predict.py         # test 이미지 폴더 일괄 추론 → runs/ 에 시각화 저장
```

### 파일

| 파일 | 용도 |
|---|---|
| `webcam_helmet.py` | 안전모 착용/미착용 웹캠 테스트 (기본 모델: `models/helmet_v2_best.pt`) |
| `webcam_person.py` | 인원 수 검출 + 추적 + "2인 1조" 규칙 미니 데모 |
| `trackers/bytetrack_person.yaml` | 저FPS(로컬 CPU)용 ByteTrack 튜닝 설정 |
| `predict.py` | 학습 가중치로 test 이미지 일괄 추론 |
| `docs/helmet_v1/`, `docs/helmet_v2/` | 학습 결과 지표·그래프·웹캠 테스트 평가 |

> `main.py` 자리는 비워둠 — 검출·추적·규칙을 통합한 파이프라인이 생기면 그것이 진입점.
> 데이터셋 다운로드·로컬 학습 스크립트는 없음 — 학습은 전부 Colab에서 진행 (위 절차 참고).

> Roboflow YOLOv8 export의 `data.yaml`은 경로가 잘못돼 있어(`../train/images`) 절대경로
> `path:` 키를 추가해야 학습이 됩니다. `datasets/`는 저장소에 포함되지 않습니다.

## 8. 오픈소스 구성 (예정)

영상 수집 OpenCV · FFmpeg / 검출 Apache-2.0 계열(예: YOLOX) / 음성 인식 faster-whisper(MIT) /
서버 FastAPI(MIT). 상용 배포 제약을 피하기 위해 검출 모델은 AGPL-3.0이 아닌 라이선스를
지향합니다. 현재 실험은 검증 속도를 위해 `ultralytics`(YOLOv8) 사용 — 데이터셋·학습
파이프라인은 포맷 호환이라 제품화 시점에 프레임워크만 교체 가능합니다.
