# rtauto_sop

**작업자 행동인식 기반 SOP 준수 지원 시스템** — AI 모델 학습/검증 저장소

알티자동화(RT Automation)의 시범 과제입니다. 이 저장소는 전체 시스템 중 **객체 검출 모델을
준비·검증하는 파트**만 담고 있습니다.

**현재 진행**: **감시단원 카메라가 담당하는 판정 항목 3개**(N인 1조 인원 수 / 보호구 착용 /
안전구역 침범)를 하나의 통합 데모(`webcam_sop.py`)로 구현 완료. 위반 발생 시 실제 브라우저
푸시 알림까지 가는 경로도 프로토타입으로 검증했습니다. 작업자 카메라가 담당하는 항목
(항목·순서, 급소포인트)은 **세정기 SOP 문서가 선행 조건**이라 착수 전입니다.

---

## 1. 시스템 개요

작업자 2인 1조 작업을 카메라로 검출해 엣지 PC가 SOP(표준작업절차)와 대조하고, 편차가
확정되면 작업자에게는 헤드셋 음성으로, 관리자에게는 휴대폰 알림으로 즉시 통보합니다.

- **시범 대상**: 세정기 작업
- **카메라 구성**: 현장 고정이 아닌 **착용형(체스트 마운트)**. 실제 작업자 1인 + 안전감시단원
  1인이 각각 바디캠을 착용(총 2대). 설비 형상·위치가 바뀌어도 같은 구성을 그대로 사용.
- **처리 위치**: 영상·음성 모두 현장 엣지 PC 1대에서 처리. 사무실 서버·관제 PC 없음.
  인터넷 회선 1개만 있으면 동작하며, 인터넷이 끊겨도 현장 경보는 계속 울림.

### 감지 항목

본사 SOP 양식에서 다음 4가지를 검출 대상으로 정의합니다.

| SOP 문서 항목 | 시스템 판정 항목 | 주 검출 경로 | 구현 |
|---|---|---|---|
| 안전관리대책 | 2인 1조 인원 수 | 감시단원 바디캠 (2~4m) | ✅ |
| 안전관리대책 | 보호구 착용 | 감시단원 바디캠 (2~4m) | ✅ |
| 위험요인 | 안전구역 침범 | 감시단원 바디캠 (광역 시점) | ✅ PoC |
| 위험요인 | 위험 자세(사다리 끝단) | 감시단원 바디캠 (광역 시점) | — |
| 항목·순서 | 단계 순서 위반 · 단계 누락 | 작업자 바디캠 (근접 시점) | SOP 필요 |
| 급소포인트 | 필수 동작 누락 · 확인 절차 생략 | 작업자 바디캠 (0.8m 이내) | SOP 필요 |
| STEP별 작업시간 | 표준 소요시간 초과 · 과속 진행 | 양 카메라 공통 (체류시간) | SOP 필요 |

카메라 2대는 **거리가 달라 담당 항목이 갈립니다.** 현재 구현된 3개는 전부 감시단원 카메라
항목이고, 작업자 카메라 채널은 아직 코드가 없습니다. 두 채널은 각자 판정한 뒤 SOP 상태
기계에서 합쳐지는 구조가 될 예정입니다.

## 2. AI의 역할

**AI는 객체 검출 · 추적 · 음성 인식(STT)에만 사용합니다.** 편차 판정과 응답 문구는 규칙
기반으로 처리하여, 판정 근거를 사람이 그대로 추적할 수 있게 합니다.

- 사람 · 안전보호구 같은 범용 객체는 **공개 사전학습 모델을 그대로 사용**하는 것이 기본
  방침입니다(별도 학습 비용 없음).
- 세정기 특유의 부품이나 급소포인트 동작처럼 공개 모델이 다루지 않는 항목만, 소량의 현장
  영상으로 미세조정(fine-tuning)합니다. 항목별 필요 여부는 1주차 현장 실측에서 확정합니다.
- **이 저장소의 헬멧 검출 실험**은 위 "보호구 착용" 항목이 공개 데이터/모델로 어느 정도
  커버되는지 사전 검증하는 작업입니다. → 아래 6절 결과 참고.

### AI 처리 흐름 (영상 경로)

```
① 스트림 수신(RTSP/H.264, FFmpeg 3fps)                    ← 웹캠으로 대체 중 (장비 입고 후 RTSP)
② 객체 검출 (YOLO 계열 1-stage: 사람·안전모·장갑 …)        ← 완료 (person, 안전모)
③ 추적·좌표화 (ByteTrack, 중복 제거, 구역 좌표 매핑)        ← 완료 (ByteTrack + ArUco 구역 매핑)
④ 상태 집계 (인원 수·보호구·구역 체류·자세, 3초 창 다수결)  ← 완료 (감시단원 채널 3항목)
⑤ SOP 대조 (구조화된 SOP와 STEP 순서·표준시간 규칙 비교)    ← SOP 문서가 없어 착수 전  ← 다음 관문
⑥ 편차 확정 (중대/주의/정상 등급 산정 → 출력 라우팅)        ← 규칙 단위는 동작, 등급 차등은 미구현
```

출력 경로는 Web Push 알림까지 프로토타입으로 연결돼 있습니다(6절). 헤드셋 음성(TTS)과
이력·클립 저장은 미착수입니다.

음성 경로는 헤드셋 PTT 버튼 입력 시에만 채널이 열리며(상시 녹음 아님), `faster-whisper`로
STT 후 키워드 규칙으로 의도를 분류해 SOP를 조회하고 TTS로 응답합니다.

## 3. 세정기 SOP 표준 문서

시스템의 판정 기준은 SOP를 구조화한 데이터입니다. 자사 SOP에 세정기 작업이 없어, 이번
과제에서 「세정기 작업 표준 문서(SOP)」를 직접 제작합니다.

현장 관찰·영상 촬영 → 작업 단계 분해 → 표준 소요시간 측정 → 급소포인트·위험요인 도출 →
현장 검토·승인 → 승인 문서를 JSON으로 변환해 판정 엔진에 적재. 산출물이 문서와 시스템
양쪽에 남고, 다른 설비로 확장할 때는 같은 양식의 SOP를 JSON으로 바꿔 끼우면 됩니다.

## 4. 데이터 흐름 (전송 구간)

| 구간 | 데이터 | 매체 | 규격 | 지연 목표 |
|---|---|---|---|---|
| ① 바디캠 → 엣지 PC | 영상 2채널 | WiFi 5GHz (SoftAP 직결, 인터넷 미경유) | RTSP / H.264 · 1080p 15fps · 대당 ~4 Mbps | 0.5초 이내 |
| ② 헤드셋 ↔ 엣지 PC | 음성 질의/경보 | Bluetooth 5.x (USB 동글) | HFP 양방향 · 16kHz 모노 · 버튼 입력 시에만 개방 | 0.3초 이내 |
| ③ 엣지 PC → 관리자 휴대폰 | 편차 알림·클립 링크 | 인터넷 (유선 랜) | HTTPS + Web Push · 미확인 시 30초 간격 재발송 | 1초 이내 |

- 영상 경로(①)와 알림 경로(③)는 **물리적으로 분리**되어, 인터넷이 끊겨도 영상 수신과 현장
  경보는 그대로 동작합니다.
- 무선 특성상 순간 끊김이 생길 수 있어, **끊긴 구간은 "위반 없음"이 아니라 "판정 보류"**로
  이력에 남깁니다. 각 연결은 1초 주기 heartbeat로 확인하고 3회 연속 미수신 시 단절로 판정합니다.

## 5. 관리자 알림

전용 앱 없이 표준 **Web Push**를 사용합니다(Android/iOS 구성 동일). 엣지 PC가 알림
수신용 웹페이지를 제공하고, 관리자가 홈 화면에 한 번 추가 후 알림을 허용하면 끝입니다.

놓침 방지 3단계: ① 잠금화면 푸시에서 색·문구로 중대 편차 구분 → ② 탭하면 전체화면 경보
(경보음·진동 반복) → ③ 확인 버튼 누를 때까지 30초 간격 재발송.

> iOS는 16.4 이상에서 홈 화면 추가 시에만 Web Push가 동작하며, 잠금화면 알림음은 OS
> 기본음으로 고정됩니다.

## 6. 학습 결과 — 안전모 착용/미착용 검출

공개 데이터만으로 "보호구 착용" 항목을 판정할 수 있는지 검증한 실험입니다.

| | helmet_v1 | **helmet_v2** |
|---|---|---|
| 데이터셋 | `hard-hat-detection-ws2wk` (668장, 착용 위주) | `joseph-nelson/hard-hat-workers` (~7,000장) |
| 클래스 | hard hat / no hard hat / not hard hat | helmet / no_helmet (person 제외) |
| 미착용 학습 표본 | 16 ~ 64 인스턴스 | 1,000+ 인스턴스 |
| mAP@50 | 0.41 | **0.96** |
| 착용 검출률 (recall) | 0.91 | **0.97** |
| **미착용 검출률 (recall)** | **0.00 ~ 0.33** | **0.95** |

- helmet_v1과 v2는 **학습 설정이 동일**하고 데이터셋만 다릅니다. 미착용 표본을 늘리자 미착용
  검출률이 0 → 0.95로 올랐습니다. → **성능 한계는 학습량이 아니라 데이터에 있었음**을 확인.
- 이 시스템의 핵심 판정 대상인 **보호구 미착용(SOP 위반) 검출이 공개 데이터로 가능**함을
  확인했습니다. 단, 현장 조건(바디캠 화각·거리·조도)에서의 성능은 1주차 실측으로 별도 검증 필요.
- 상세: [`docs/helmet_v1/metrics.md`](docs/helmet_v1/metrics.md), [`docs/helmet_v2/metrics.md`](docs/helmet_v2/metrics.md),
  [`docs/helmet_v2/webcam_test.md`](docs/helmet_v2/webcam_test.md)

가중치 파일(`*.pt`)은 용량 문제로 저장소에 포함하지 않습니다 (로컬 `models/` · Google Drive 보관).

### 웹캠 테스트에서 확인한 것

로컬 웹캠 근접 조건에서 helmet_v2는 착용/미착용을 신뢰도 있게 구분합니다(confidence 0.7~0.9).
다만 다음은 다음 단계 설계에 반영해야 합니다.

- **"helmet 검출 = 착용"이 아님** — 손에 든 헬멧도 `helmet`으로 잡힘. 실제 착용 판정은
  person/head 박스와 helmet 박스의 공간 관계(겹침)로 규칙 단계에서 처리해야 함.
- **가림에 취약** — 얼굴이 가려지면 인물 자체가 미검출 → "위반 없음"이 아니라 판정 보류 처리.
- **원거리 소형 객체(2~4m, 안전모 22~35px) 성능은 미검증** — 바디캠 입고 후 현장 실측 대상.

### 통합 데모 — 감시단원 채널 3규칙 (`webcam_sop.py`)

person 검출+추적, helmet_v2, ArUco 구역 인식을 한 루프에서 결합했습니다. 규칙 3개 모두
**지속 시간을 채워야 확정되고, 정상 복귀도 지속돼야 해제**되는 방식(기획안 5.6절)입니다.

| 규칙 | 조건 | 기본 지속시간 |
|---|---|---|
| N인 1조 | 인원 수 ≠ N | 3초 |
| 보호구 미착용 | 특정 인물이 미착용 상태 | 10초 |
| 안전구역 침범 | 특정 인물의 발 위치가 구역 안 | 3초 |

두 가지 설계 원칙이 들어가 있습니다.

- **"헬멧 박스가 보이면 착용"이 아님** — person 박스 안에 helmet 박스의 중심점이 들어오는지로
  실제 착용 여부를 판정합니다. 손에 든 헬멧이 착용으로 오판되던 문제를 해결했습니다.
- **모르면 위반도 정상도 아님(판정 보류)** — 보호구 박스를 못 찾은 사람, 구역 마커가 안 보이는
  구간은 "미확인"으로 두고 위반 처리하지 않습니다.

필요 인원 수(2/3/4인 1조 등)와 지속시간은 코드 수정 없이 실행 인자로 바꿉니다:
```bash
python webcam_sop.py --crew 3 --crew-hold 5 --helmet-hold 15 --zone-hold 5
python webcam_sop.py --no-zone          # 마커를 준비 못 했을 때 안전구역만 끄기
```

### 안전구역을 "화면 좌표"가 아닌 "실세계 기준"으로 잡는 법

착용형 카메라는 계속 움직이므로, 화면에 고정 폴리곤을 그려두면 카메라가 돌아가는 순간
그 좌표가 엉뚱한 곳을 가리킵니다. 대신 위험구역 네 모서리에 **ArUco 마커**를 두고 매 프레임
마커 위치로 구역을 다시 계산합니다 — 카메라가 움직여도 마커가 보이는 한 구역이 따라오고,
마커가 안 보이면 판정 보류로 침묵합니다.

바디캠은 호흡·발걸음만으로도 미세하게 흔들려 "이번 프레임에 마커 4개 동시"라는 조건이 쉽게
깨집니다. 그래서 **최근 0.4초 안에 본 적 있는 마커는 그 위치를 그대로 사용**해 순간 미검출을
흡수합니다. 마커 1개가 아예 가려져 3개만 보일 때는 **평행사변형 근사**(사각형 대각선의
중점이 같다는 성질)로 4번째 모서리를 추정해 계속 판정합니다 — `--no-zone-estimate`로 끌 수
있습니다. 화면에서 초록 점 = 실시간 인식, 주황 점 = 최근 기억, **빈 마젠타 원 = 추정치**로
구분됩니다. 마커가 2개 이하로 줄면 추정도 불가능해 판정 보류로 돌아갑니다.

`generate_markers.py`로 마커 4장을 만들어 `markers/`에 저장합니다. 웹캠 수준의 개념 검증은
완료했고, 실전 적용 전 마커 재질(방수)·인식 가능 거리(4~10m)·부착 높이를 현장에서 확정해야
합니다. 평행사변형 근사는 카메라가 정면에 가까울 때 잘 맞는 근사치라 각도가 심하게 기울어진
조건에서의 오차도 실측으로 확인해야 합니다.

### 관리자 알림 프로토타입 (`push_server.py`)

기획안 5.5절의 "전용 앱 없이 표준 Web Push" 구조를 로컬에서 재현했습니다. 브라우저로 구독
페이지에 접속해 알림을 허용하면, 위반이 확정되는 순간 실제 푸시 알림이 도달합니다.

```bash
python generate_vapid_keys.py                    # 최초 1회
uvicorn push_server:app --port 8000              # 터미널 1 → localhost:8000 에서 구독
python webcam_sop.py --push-url http://localhost:8000/notify   # 터미널 2
```

같은 위반이 해제됐다 금방 다시 걸리는 **반복(flapping)은 억제**합니다 — 기본 5분 안에 재발하면
매번 알리지 않고 누적하다가 3회째에 "N회 반복" 요약 알림 1번만 보냅니다
(`--repeat-cooldown-min`, `--repeat-threshold`로 조정).

그래도 프로토타입 수준입니다 — localhost 전용(HTTPS 없음), 구독 정보는 JSON 파일 저장, 30초
재발송·확인(ACK)·등급별 차등 발송은 미구현.

### 현재 완성도

**감시단원 카메라가 담당하는 판정 항목 3개**(인원 수 / 보호구 / 안전구역)와 출력 경로 중
관리자 알림까지가 동작합니다. 아직 없는 것:

- 작업자 카메라 채널 전체 (항목·순서, 급소포인트) — SOP 문서가 선행 조건
- SOP 규칙 판정 엔진, STEP별 소요시간 — 마찬가지로 SOP 문서 필요
- 2채널 동시 수신, 헤드셋 음성(TTS), 이력·클립 저장, 엣지 PC 통합, heartbeat

바디캠이 입고돼도 "꽂으면 시스템이 도는" 상태가 아닙니다. RTSP 2채널 수신, 현장 거리·조도
기준 재튜닝, 마커 실측, GPU 동시 부하 검증이 별도로 필요합니다. 지금까지 한 작업의 가치는
**알고리즘 리스크를 미리 걷어내고 재사용 가능한 모듈을 확보한 것**입니다.

## 7. 이 저장소 사용법

### 환경

- Windows + Git Bash, Python 가상환경(`venv/`)
- 로컬 GPU는 GTX 1050 Ti(4GB)로 학습엔 약함 → **학습은 Google Colab (T4), 로컬은 추론만**
- 로컬 `torch`는 CPU 빌드. 추론(웹캠)은 CPU로 실시간 충분

```bash
source venv/Scripts/activate                       # 가상환경 활성화
pip install --no-cache-dir -r requirements.txt      # 최초 1회 (또는 새 패키지 추가 후)
```

### 학습 (Google Colab)

1. Colab 새 노트북 → 런타임을 T4 GPU로 설정
2. 이 저장소 clone, `pip install ultralytics roboflow`
3. Colab Secrets(🔑)에 `ROBOFLOW_API_KEY` 등록 후 데이터셋 다운로드
4. data.yaml 경로 수정 + (필요 시) 클래스 재매핑
5. `YOLO("yolov8n.pt").train(data=..., epochs=50, imgsz=640, batch=32, device=0)`
6. `best.pt`, `results.png`, `confusion_matrix.png`, `results.csv` 를 `files.download()` 로 내려받기
7. 로컬 `models/` · `docs/<name>/` 에 배치 후 커밋

### 실행 (로컬)

```bash
# 메인 통합 데모 ('q' 종료)
python generate_markers.py   # 최초 1회 — 마커 4장 생성, 프린트해서 구역 네 모서리에 배치
python webcam_sop.py         # 3규칙 전부. --crew N 등 파라미터는 --help 참고
python webcam_sop.py --no-zone                # 마커 없이 인원수+보호구만

# 알림까지 연동하려면 (터미널 2개)
python generate_vapid_keys.py                 # 최초 1회
uvicorn push_server:app --port 8000           # 터미널 1 → 브라우저로 localhost:8000 접속해 구독
python webcam_sop.py --push-url http://localhost:8000/notify   # 터미널 2

# 단일 기능 검증용 (문제 생겼을 때 원인 분리에 유용)
python webcam_helmet.py     # 안전모만
python webcam_person.py     # 인원 수 + 추적만
python webcam_zone.py       # 안전구역만
python debug_aruco.py       # 마커가 인식되는지만 (조명/거리/인쇄 문제 진단)
python predict.py           # test 이미지 폴더 일괄 추론 → runs/ 에 시각화 저장
```

### 파일

| 파일 | 용도 |
|---|---|
| **`webcam_sop.py`** | **메인 통합 데모** — 감시단원 채널 3규칙(N인 1조 + 보호구 + 안전구역) |
| `push_server.py` | Web Push 알림 프로토타입 서버 (FastAPI, 구독 페이지 + `/notify`) |
| `generate_vapid_keys.py` | Web Push용 VAPID 키 생성 (최초 1회) |
| `generate_markers.py`, `markers/` | 안전구역용 ArUco 마커 생성/보관 |
| `trackers/bytetrack_person.yaml` | 저FPS(로컬 CPU)용 ByteTrack 튜닝 설정 |
| `requirements.txt` | 로컬 실행 환경 (학습은 Colab이라 무관) |
| `webcam_helmet.py`, `webcam_person.py`, `webcam_zone.py` | 단계별 검증용 단일 기능 스크립트 |
| `debug_aruco.py` | 마커 인식 진단 (코드 문제 vs 조명·거리 문제 분리) |
| `predict.py` | 학습 가중치로 test 이미지 일괄 추론 |
| `docs/helmet_v1/`, `docs/helmet_v2/` | 학습 결과 지표·그래프·웹캠 테스트 평가 |

> `main.py` 자리는 비워둠 — 작업자/감시단원 2채널을 합친 파이프라인이 생기면 그것이 진입점.
> 데이터셋 다운로드·로컬 학습 스크립트는 없음 — 학습은 전부 Colab에서 진행 (위 절차 참고).
> VAPID 키·구독 정보(`*.pem`, `push_subscriptions.json`)는 저장소에 포함되지 않습니다.

> Roboflow YOLOv8 export의 `data.yaml`은 경로가 잘못돼 있어(`../train/images`) 절대경로
> `path:` 키를 추가해야 학습이 됩니다. `datasets/`는 저장소에 포함되지 않습니다.
